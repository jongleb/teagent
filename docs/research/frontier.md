# teagent leads in design, trails in evidence

Between 2025 and November 2026 three research communities converged on teagent's thesis without meeting each other. Code-as-action papers showed that a model writing a program beats a model emitting JSON tool calls on long chains and wide fan-out, though not on short or parallel-only tasks. Programming-language groups (tacit and LACUNA at EPFL, Language-Based Agent Control, ETAS, λA) began typechecking agent-written programs before anything runs. Systems groups (Atomix, DeltaBox, Speculative Actions) made agent effects transactional, cheap to roll back, and safe to branch. **No system found in this research combines all three in one semantics**: a pure, statically typed language the model writes whole; effects that exist only as a reified `Task` tree carrying provenance labels; and a handler that stages every write, including those from the shell, in an overlay that commits once and replays exactly. teagent does all of that today, so its architecture sits in an empty niche. Its evidence does not yet match. The headline measurement, 28 of 28 programs compiling on the first try, is a feasibility datum: 28 in-house tasks, one frontier model, one run each, no baseline arm, and runtime fixes made during the measurement. Reviewers in late 2026 expect a factorial model × harness study on Terminal-Bench 2.x or SWE-bench Pro with k ≥ 5 trials, pass^k and cache-adjusted dollars per solved task. To lead, teagent should do four things. First, run the efficiency benchmark with its own MCP tools as the tool-call arm, which holds the sandbox, overlay and handler fixed and so isolates the action paradigm better than any published comparison. Second, give holes Hazel-style type context and ablate the tool description. Third, turn static leak checking and a verified staging handler into its PL contribution. Fourth, build a Dartea training pipeline with open-weight teachers. The research questions teagent is best placed to own are static noninterference for an LLM-written TEA program, stage-commit soundness, "live" holes filled with both types and runtime values, and a three-way comparison of typed, untyped and JSON action spaces on coding benchmarks.

**How to read the sourcing.** The research notes behind this report mark how firm each claim is, and the report keeps those marks. **[AR]** means a number reported by the authors or vendor and not independently reproduced; almost every number in this field is of this kind. **[2nd]** means the claim was seen only through a secondary summary, blog or aggregator, not the primary text. **[bg]** means it comes from the researchers' background knowledge, with a known primary source that was not re-opened during this research. *Abstract only* or *snippet only* means the full paper was not read. Statements about teagent itself come from the working tree on 2026-11-11 ([README](../README.md), [micro-OS note](../docs/micro-os.md), [manual](../lib/manual/Manual.md), [ABI](../docs/abi.md)). Security is covered in the earlier report, [LLM agent security for teagent](../docs/research/llm-security.md), which this report builds on without repeating.

## Programs beat tool calls only where chains run long

The canonical result is still **CodeAct** (ICML 2024), which reports "up to 20% higher success" for Python actions than for JSON or text actions across 17 LLMs **[AR]** ([arXiv 2402.01030](https://arxiv.org/abs/2402.01030)). A secondary summary gives its M3ToolEval numbers for GPT-4-1106 as 74.4% vs 52.4% success and 5.5 vs 7.6 turns **[AR][2nd]**. The best-controlled comparison to date is **"The Bitter Lesson of Tool Calling"** (PwC, August 2026). It runs 14 models on a 309-entry BFCL v4 subset at temperature 0, gives the model typed Python stubs generated from the schemas, and fixes the number of LLM calls per entry. Programmatic calling matched or beat JSON in **11 of 14 models**. On chaining, Claude Sonnet 5 rose from 80.8% to 96.2%, with an 18.8-point gap at chain length 12 and above. Under JSON, Sonnet 5 fell to **0% at a fan-out of 100 calls** while the program arm stayed at 100%. Chaining wall time roughly halved for 13 of 14 models **[AR]** ([arXiv 2608.06370](https://arxiv.org/html/2608.06370v1)). The same paper is the strongest warning against a universal claim. Code mode was **14.1 points worse on the parallel categories**. It carried a fixed input overhead of about 1.5× on short chains, with a token crossover near 26 calls. GPT-5 was 2.8× *slower*. GPT-4.1 fell from 98.1% to 40.4% on chaining because it wrote literal `\n` escapes that broke its scripts. Its stubs only echo their arguments, so return values are never exercised.

Field results point the same way. AWS's strands-code-agent comparison on the Data Agent Benchmark held Claude Opus 4.6, the SDK and the database layer fixed. It reports 78% fewer input tokens, 35% fewer cycles and 56% less wall time, but success was 30/54 vs 28/54, which is within noise for a single vendor run **[AR]** ([AWS](https://builder.aws.com/content/3GX0kIJThfb93iJIQ7eGG4nh2Zx)). PyRUA-Lean, a robotics study, counts "49% fewer LLM calls and 65% fewer input tokens" only on *jointly solved* instances, so failures cannot bias the efficiency numbers **[AR]** ([arXiv 2610.01939](https://arxiv.org/abs/2610.01939)). The one study on coding agents with the harness held fixed, "When Does Restricting a Coding Agent to execute_code Help?" (KDD 2026 workshop), found **pass rates statistically tied** across tool surfaces in Claude Code and Codex CLI. The cost signal appeared only after cache adjustment, and on SWE-bench with Claude the code-only arm was 14.4% costlier (not significant), driven by the cost of failed runs **[AR]** ([arXiv 2607.10569](https://arxiv.org/abs/2607.10569)). One more caveat is that code actions raise completion tokens by about 36% according to CaveAgent, whose snippet was garbled and needs verifying ([arXiv 2601.01569](https://arxiv.org/pdf/2601.01569)).

The vendor "code modes" offer a mechanism but no effect sizes. Cloudflare's Code Mode turns MCP schemas into a TypeScript API that runs in a network-less V8 isolate, publishes no numbers, and never says whether the code is typechecked ([Cloudflare](https://blog.cloudflare.com/code-mode/)). Anthropic's often-quoted **150,000 → 2,000 tokens (98.7%) is an illustrative scenario, not a benchmark** ([Anthropic](https://www.anthropic.com/engineering/code-execution-with-mcp)). Its measured Programmatic Tool Calling figures are modest: tokens fell from 43,588 to 27,297 (−37%) and GAIA rose from 46.5% to 51.2% **[AR, internal]** ([Anthropic](https://www.anthropic.com/engineering/advanced-tool-use)). OpenAI's JavaScript code mode publishes nothing and tells users to keep writes and approval-sensitive actions on direct calls ([OpenAI docs](https://developers.openai.com/api/docs/guides/tools-programmatic-tool-calling)). That is precisely the gap teagent fills with staged writes. Plan-then-execute systems are the other ancestor. LLMCompiler reports up to 3.7× lower latency and 6.7× lower cost than ReAct **[AR]** ([PMLR](https://proceedings.mlr.press/v235/kim24y.html)), but a static DAG cannot react to what it observes. teagent keeps that adaptivity inside one program through `andThen` branches and holes.

**Where teagent stands.** teagent is the extreme point on this axis, one whole program per step, so the literature predicts its advantage is largest on long, multi-file coding tasks and smallest on one-shot lookups. Two mechanisms address documented failure modes directly. The compile step rejects the "literal `\n`" class of script breakage before any effect runs, and the driver already flags a model that "answers before it has looked at anything", the parametric-answer failure the Bitter Lesson paper describes. Two facts cut the other way. First, **`batch` runs its tasks in order** ([manual](../lib/manual/Manual.md)), so teagent does not yet collect the parallel-execution gains of LLMCompiler or Quasar. Second, its tool description of about 10,000 characters (the manual plus the cut `Agent` signatures) is exactly the kind of fixed overhead that loses on short tasks. **No published study compares code actions with JSON calls on SWE-bench- or Terminal-Bench-class tasks with the same model, and none compares typed-and-checked code, untyped code and JSON in one design.** That slot is open.

## Checking before running became the PL consensus, and types work as context

Four 2026 papers enforce types on agent programs before execution. **LACUNA** (EPFL, May 2026) makes each action an `agent[T](task)` hole that the model fills with Scala, typechecked against the surrounding program. On BrowseComp-Plus **8.6% of generations were rejected before execution**, with 0.7 retries per query, and τ²-bench reached 76.0%, "on par with the baseline agent" **[AR]** ([arXiv 2605.28617](https://arxiv.org/abs/2605.28617)). **tacit** ("Tracking Capabilities for Safer Agents", same group, March 2026) compiles Scala 3 snippets under capture checking in safe mode. Only **0.32–7.93% of snippets needed any retry**, with a mean of 1.06–1.39 consecutive retries. τ²-bench pass^1 rose 0.8–3.7 points over tool calling, while SWE-bench Lite fell from 43.3% to 41.7% **[AR]** ([arXiv 2603.00991](https://arxiv.org/html/2603.00991v2)). **Language-Based Agent Control** (Zhou, D'Antoni, Polikarpova) rejects unsafe programs in the typechecker and reportedly uses Haskell as host; its abstract has no numbers **[2nd for the host language]** ([arXiv 2605.12863](https://arxiv.org/abs/2605.12863)). **ETAS** types each computation by an effect row and an abstract action trace, emits residual runtime obligations where a static proof fails, and proves preservation, progress and handler trace-transparency, with no empirical evaluation *(abstract only)* ([arXiv 2607.17780](https://arxiv.org/abs/2607.17780)).

The best evidence for *why* frontier models can write a niche typed language is the Hazel work on typed holes (OOPSLA 2024). Its benchmark, MVUBench, is literally model-view-update, which is Elm-architecture. For GPT-4, type definitions in context "seem absolutely necessary". Adding the headers of functions that produce the target type roughly **tripled** tests passed, and up to two rounds of error feedback gave about 4× without headers and 1.5× with them. Static, type-directed retrieval beat vector retrieval. The gains were about twice as large in Hazel as in TypeScript, which supports the authors' claim that lower-resource languages benefit more **[AR]** ([arXiv 2409.00921](https://arxiv.org/html/2409.00921v1)). The paper is internally inconsistent: it says "320 trials" while its design implies 800. Krishnamurthi and Flatt (June 2026) gave leading agents ML-style programs with injected type errors under four levels of error detail. Richer messages, such as the unification trace, generally helped; a type system helped more than test failures alone; and once the type error was fixed, the program usually passed every semantic test **[AR, abstract only]** ([arXiv 2606.01522](https://arxiv.org/abs/2606.01522)). This supports teagent's rule that compiler reports go to the model as Elm prints them, with `Hint:` lines added rather than text removed.

Type-*constrained decoding* is the decoding-side complement, and it needs logit access. Mündler et al. (PLDI 2025) found that **94% of compile errors are type errors, not syntax errors**. Prefix automata that reject any token prefix that cannot complete to a well-typed program cut compile errors by more than half. Versions of the paper report different figures: 70.9% on average with +16.2% functional correctness in the workshop version, and about 75% on HumanEval and 56% on MBPP against 9% and 5% for syntax-only constraints **[AR]** ([arXiv 2504.09246](https://arxiv.org/abs/2504.09246)). Grammar-only constraints distort the model's distribution ([arXiv 2405.21047](https://arxiv.org/abs/2405.21047)), and their benefit shrinks with scale: on Spider, +13 points at 0.5B but about +1 at 7B **[AR]** ([GRID](https://www.alphaxiv.org/abs/2607.11951)). Drafting unconstrained and then decoding under constraint conditioned on the draft adds 10.6 points over plain constrained decoding **[AR]** ([arXiv 2603.03305](https://www.alphaxiv.org/abs/2603.03305)). That is teagent's shape already: an unconstrained whole program followed by a typecheck.

Verified generation shows the same data-availability effect at a harder level. Across 12,504 vericoding tasks, the union of models succeeded on about **82% in Dafny, 44% in Verus and 27% in Lean** **[AR]** ([arXiv 2509.22908](https://arxiv.org/pdf/2509.22908)). AlphaVerus bootstrapped Verus from Dafny by translation and had to **filter misaligned specifications to stop reward hacking** **[AR]** ([arXiv 2412.06176](https://arxiv.org/pdf/2412.06176)). The lesson for teagent is that a check means something only when the harness, not the model, fixes the contract. In teagent the OS value, the cut `Agent` module and `rules.elm` are written by the person, and the model can never write them.

Low-resource languages remain hard. Frontier models solve "much fewer" OCaml homework problems than Python or Java, though they are strongest at fixing syntax and type errors **[AR, abstract only]** ([arXiv 2603.05646](https://arxiv.org/abs/2603.05646)). FPEval finds significantly higher error rates in Haskell and OCaml than in Scala or Java ([arXiv 2601.02060](https://arxiv.org/html/2601.02060v1)). A small Advent-of-Code blog benchmark had Elm solved on the first try by 4 of 10 models, against 10 of 10 for Python ([blog](https://benjamin-thomas.github.io/posts/aoc-2025-llm-benchmark-elm)). The closest published analogue of Dartea is PyLang, a language absent from all pretraining. With a spec and snippets, Claude Sonnet 4.5 reached **58.0% in PyLang against 87.5% in Python**, and **idiom snippets mattered most while spec rules alone sometimes hurt** **[AR]** ([arXiv 2605.15607](https://arxiv.org/html/2605.15607v2)).

**Where teagent stands.** A 28/28 first-try compile rate for a "no-resource" dialect of a low-resource language is notable, and there is no direct comparator. LACUNA's 8.6% rejection and tacit's ≤7.93% retry rate come from other tasks and from Scala. The literature attributes such results to the type information in the prompt (Hazel, PyLang), so that conditioning is the claim to make and the variable to ablate. teagent's distinctive position is that it *enforces* types, as LACUNA and tacit do, where Cloudflare and the Bitter Lesson stubs use types only as context. It also reifies effects as a value and replays them, which neither of those does. First-try compilation is not first-try correctness: 19 of the 20 small tasks were right on the first run ([README](../README.md)). LACUNA reports rejections, not success, so teagent should report both numbers.

## Runtimes made effects transactional; teagent got there locally first

The "agent OS" label covers two things in the literature, and neither of them is effect containment. AIOS (COLM 2025) is a scheduler and resource manager for LLM calls shared by many agents and reports up to 2.1× faster execution **[AR]** ([arXiv 2403.16971](https://arxiv.org/abs/2403.16971)). MemGPT and Letta page the context window like virtual memory ([Letta](https://www.letta.com/blog/agent-memory)). The 2026 "agent kernel" preprints mediate syscalls with eBPF (AgentKernel, which admits its policy engine shares a process with the agents), gate MCP at kernel level (Governed MCP), or argue that agents behave like ring-0 operating systems (AaOS), all *snippet only* ([AgentKernel](https://arxiv.org/pdf/2609.29647), [Governed MCP](https://arxiv.org/pdf/2604.16870), [AaOS](https://arxiv.org/html/2610.33753)). The search found no OSDI, SOSP or EuroSys agent-OS paper. teagent's micro-OS differs in kind, not in degree. The OS is a typed Dartea value that only narrows, and it *generates* the syscall table the program compiles against. A missing call is a compile error, "pledge checked ahead of time", and is not filtered after the fact ([micro-OS note](../docs/micro-os.md)).

The transactional frontier is **Atomix** (ICLR 2026). It classifies effects as bufferable, reversible-external or irreversible, gives each an idempotency key and a compensation handler, and commits only when per-resource frontiers show that no earlier conflicting work can still arrive. It reports microsecond-scale overhead **[AR]** ([arXiv 2602.14849](https://arxiv.org/abs/2602.14849)). **DeltaBox** (May 2026) stacks a new writable file layer at each checkpoint and forks processes from frozen templates. It reports **14 ms checkpoints and 5 ms rollbacks** **[AR]**, and its MCTS share of wall clock spent on state management falls from 47–77% to 3–6% **[2nd]** ([arXiv 2605.22781](https://arxiv.org/abs/2605.22781)). Products are weaker. Claude Code's documentation states that **checkpointing "does not track files modified by bash commands"** ([Claude Code docs](https://code.claude.com/docs/en/checkpointing)). Durable-execution engines such as Temporal replay a journal but leave determinism to developer discipline. Code changes break in-flight replays, and a changed prompt template makes cached responses stale ([Temporal](https://temporal.io/blog/of-course-you-can-build-dynamic-ai-agents-with-temporal)). Speculative Actions (ICLR 2026 oral) runs guessed next actions in parallel and keeps them only on a match, for about 20% lossless speedup (30% in the ICLR listing) **[AR]** ([arXiv 2510.04371](https://arxiv.org/abs/2510.04371)). A Salesforce follow-up restricts speculation to side-effect-free calls ([arXiv 2607.12236](https://www.alphaxiv.org/abs/2607.12236.md)).

The sandbox market converged on Firecracker microVMs, gVisor and containers. Vendors claim 90–150 ms creation, but **independent measurement lands at 0.7–1.3 s** ([LogRocket](https://blog.logrocket.com/comparing-ai-agent-sandbox-platforms-e2b-modal-daytona-and-more/)). The nearest neighbour to teagent's overlay is **Turso AgentFS**: a copy-on-write overlay whose delta is one SQLite file, mounted over FUSE or NFS, with `agentfs run` and `diff` commands ([Turso docs](https://docs.turso.tech/agentfs/guides/overlay)). For wrapping existing agents, Anthropic's `srt` drops the Linux network namespace and leaves Unix-socket proxies as the only way out ([GitHub](https://github.com/anthropic-experimental/sandbox-runtime)). Docker Sandboxes gives each agent a microVM ([Docker docs](https://docs.docker.com/ai/sandboxes/)). Neither stages writes for review, commits them once, or replays a session. Branching has become practical. One ICML 2025 paper avoided MCTS because "environment states cannot be easily saved" ([arXiv 2505.13652](https://arxiv.org/html/2505.13652v1)), while BPO (July 2026) branches K−1 siblings at high-entropy steps. BPO pays 0.6–4.2% of rollout time for snapshots and beats GRPO, for example 29.8 vs 24.0 on SWE-bench Verified with Qwen2.5-7B **[AR]** ([BPO](https://www.alphaxiv.org/abs/2607.14171.md)). On interfaces, MCP moved to the Linux Foundation's Agentic AI Foundation on 9 December 2025 and added async Tasks **[2nd]** ([WorkOS](https://workos.com/blog/mcp-2025-11-25-spec-update)). OpenAI's Sandbox Agents standardized a workspace "Manifest" across about eight providers ([OpenAI](https://openai.com/index/the-next-evolution-of-the-agents-sdk/)). **Nobody standardizes effect semantics**: whether a call is staged, reversible or irreversible, and how it commits or aborts.

| Axis | Frontier | teagent today | Verdict |
| --- | --- | --- | --- |
| Local write containment | AgentFS overlay; Claude Code `/rewind` excludes bash | overlay that `shell` sees through an APFS clone or reflink copy; one commit; `--undo` covers shell writes | ahead |

| Rollback speed | DeltaBox 14 ms / 5 ms **[AR]**; vendors ~0.7 s measured | 0.32 s to clone 2,093 files per contained shell ([README](../README.md)); undo latency unmeasured | unmeasured |

## Effects, labels and protocols each have a paper; nobody has all three

The field now agrees on the slogan "an LLM call is an effect and the runtime is its handler". Di Wang's composable effect handlers separate workflow logic from LLM and I/O operations, and get about 10× speedup on Tree-of-Thoughts by having handlers introduce parallelism **[AR]** ([arXiv 2507.22048](https://arxiv.org/abs/2507.22048)). λA extends the simply typed lambda calculus with oracle calls and bounded fixpoints, mechanized in 1,519 lines of Coq with 42 theorems and no admits. It finds **94.1% of 835 real agent configurations "structurally incomplete"** **[AR]** ([arXiv 2604.11767](https://arxiv.org/abs/2604.11767)). ETAS's runtime classifies events as requested, handled, denied or committed and proves that handlers cannot hide requests from audit. That lattice maps almost one to one onto teagent's perform, stage, refuse and commit. Temporal is effects-as-data in practice, without the types. The search found **no Koka, Effekt or Unison deployment as an agent runtime**, no evaluated system that uses handlers to mock or replay agents, and no formalization of replay soundness for LLM agents ([Zylos](https://zylos.ai/research/2026-03-15-effect-systems-algebraic-effects-ai-agent-runtimes)).

Languages for agents to write fall into three generations. The first is prompting DSLs (LMQL, DSPy, SGLang) **[bg]**. The second is typed model interfaces (BAML, TypeChat, and MTP's `by llm`, OOPSLA 2025), which are now a commodity ([MTP](https://arxiv.org/abs/2405.08965v5)). The third is languages for the agent itself to write: Quasar, tacit, CaMeL's Python subset, ETAS. Quasar's key move is to separate pure computation from external actions, which buys automatic parallelization of external calls, conformal uncertainty sets, and user validation of actions ([arXiv 2506.12202](https://arxiv.org/abs/2506.12202)). **No surveyed system uses an Elm- or TEA-shaped pure functional language as the agent's action language.** Tacit uses Scala, Quasar and CaMeL use Python subsets, and ETAS is bespoke.

Capabilities and information flow are where the principled defences now live. Tacit's `Classified[T]` admits only *pure* functions in `map`, so a closure that captures a file capability is a compile error. With that wrapper, **100% of 131 injection and malicious-task trials per model were blocked** for both Claude Sonnet 4.6 and MiniMax M2.5, with utility at 99.2% and 90.0% **[AR]** ([arXiv 2603.00991](https://arxiv.org/html/2603.00991v2)). Without it, security on the 11 malicious tasks was 81.8% for Sonnet and 27.3% for MiniMax. These are the same results as the 98.5% and 91.6% overall figures in another note, measured over a different denominator. CaMeL enforces the same principle dynamically and solves 77% of AgentDojo tasks with provable security against 84% undefended **[AR]**; v1 reported 67% ([arXiv 2503.18813](https://arxiv.org/abs/2503.18813)). FIDES adds confidentiality and integrity labels refined by type information ([arXiv 2505.23643](https://arxiv.org/pdf/2505.23643v2)). The security report covers how these designs fare under attack. The PL point is this: **in Elm every function outside `Task` is already locally pure**, so teagent gets tacit's central mechanism for free. The only leak channel left is a `Task` constructor, which makes a label-indexed `Task` a small and checkable extension, not a new type system.

Two further strands give teagent ready-made research directions. ZipperGen (ISoLA 2026) specifies multi-agent coordination as message sequence charts and projects them to deadlock-free local programs, even when an LLM generates the workflow at run time ([arXiv 2604.17612](https://arxiv.org/abs/2604.17612)). That fits a spawn graph the model writes. The GenLM stack treats constrained generation as probabilistic conditioning and runs sequential Monte Carlo with grammar and semantic potentials, letting **small open models beat models more than 8× larger** **[AR]** ([ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/a2d537e69a6c6638a3630eef835f07de-Abstract-Conference.html)). No paper applies SMC to *agent action programs* rather than output strings. teagent interprets `Ir.Ast` rather than using OCaml's one-shot continuations, so it can clone interpreter state. That is the multi-shot capability particles need. The search found no work at all on budgets or costs as effects, meaning token or time quotas in the type.

## The harness moves scores more than the model, and reviewers now demand proof

SWE-bench Verified is finished as a headline benchmark. OpenAI stopped evaluating on it in February 2026, citing contamination and flawed tests ([OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)). A co-creator called it "saturated at 93.9%" ([HN](https://news.ycombinator.com/item?id=47912620)). Its successor has problems of its own: SWE-Bench Pro Verified found gold-solution leakage that enabled reward hacking, plus mis-scoped tests, and some models scored "substantially worse" after the fix ([arXiv 2609.08149](https://arxiv.org/abs/2609.08149)). The Agentic Benchmark Checklist found outcome-validity flaws in **7 of 10 popular agentic benchmarks**, with relative distortions of up to 100% ([arXiv 2507.02825](https://arxiv.org/html/2507.02825v5)). **Terminal-Bench 2.0** is the most runtime-friendly option. It has 89 curated tasks, and its tests check the *final container state*, not the agent's commands. Its runner, Harbor, already plugs in Claude Code, Codex CLI, OpenHands, mini-SWE-agent and Terminus 2 ([arXiv 2601.11868](https://arxiv.org/pdf/2601.11868)).

The dominant 2026 critique favours a runtime paper. In a controlled 3 × 3 grid, **harness variance was 7.8× model variance, and 6 of 9 model-pair rankings reversed** depending on the harness. Claude Opus 4.5 scored 45.9% on SWE-bench Pro under Scale's SEAL scaffold and 55.4% under Claude Code **[AR]** ([arXiv 2605.23950](https://arxiv.org/html/2605.23950v1)). The same paper proposes a seven-layer **Harness Card** (Execution, Tool, Context, Scheduling, Observability, Verification, Governance) and either locked-harness or factorial protocols. A June 2026 survey of Terminal-Bench entries found a median best-to-worst harness gap of 13.6 points per model **[2nd]** ([arXiv 2606.20683](https://arxiv.org/pdf/2606.20683)). HAL (ICLR 2026) made cost-aware Pareto reporting a norm, with 21,730 rollouts. In one of its examples a scaffold spent $1,577 for 40% where another spent $171 for 42% **[AR]** ([arXiv 2510.11977](https://arxiv.org/abs/2510.11977v1)). Reliability is now measured as pass^k, from τ-bench **[bg]**. A GPT-4o agent above 60% on one run fell below 25% when a task had to pass 8 of 8 times **[2nd]** ([tinyfish](https://current.tinyfish.ai/issue/29/foundations/article/16274/what-a-benchmark-score-actually-contains)).

Together these define what reviewers will accept. They want external benchmarks with a validity audit, the model held fixed against strong harness baselines, at least two or three models, k ≥ 3–5 trials with bootstrap CIs and paired tests, cost per solved task, ablations that isolate the runtime's mechanisms, and released artefacts. teagent's measurement meets none of these yet, and its "after fixes" result is, strictly, tuning on the evaluation set. The opening is that teagent's architecture maps cleanly onto the Harness Card layers where disclosure is weakest, Observability and Governance. Its exact replay logs could also become an evaluation artefact no other harness ships. Anyone can re-derive every effect without spending API money, and audit for reads of hidden tests, the leakage SWE-Bench Pro Verified found. **The novelty of deterministic replay as an eval artefact was not checked by a targeted search**, so it must not be claimed as a first until it is. Security evaluation should follow the plan in the [security report](../docs/research/llm-security.md#benchmarks-that-would-make-teagents-claims-measurable). The evaluation notes add one refinement: split attack success into *intent* (the program attempted the action, visible in the log) and *impact* (the effect landed on the host or in the committed diff). teagent is unusually able to show intent without impact, and it should state the argument-level limit openly, for example a backdoor written into an approved patch.

## A Dartea model is a 2,000-task project, not a lab-scale one

By 2026 open software agents share one recipe: thousands of executable tasks, then supervised fine-tuning on teacher trajectories that passed their tests, then on-policy RL with a binary test reward. The data needed is small. SWE-Gym fine-tuned Qwen2.5-Coder-32B on **491 trajectories** and reached 32.0% on SWE-bench Verified with a verifier **[AR]** ([arXiv 2412.21139](https://arxiv.org/html/2412.21139v2)). SWE-smith used 5,016 trajectories for 40.2% **[AR]** ([arXiv 2504.21798](https://arxiv.org/pdf/2504.21798)). DeepSWE reached 42.2% with RL only, on about 4.5k problems **[AR]** ([Together](https://together.ai/blog/deepswe)). RL on a base that can barely do the task adds little: SkyRL moved Qwen3-8B from 3.6% to 9.4% **[AR]** ([Sky](https://sky.cs.berkeley.edu/project/skyrl/)). SFT first, then RL, wins at every size below about 32B. Kimi-Dev's finding that single-shot "agentless" skills transfer as a prior for agents suggests training Dartea synthesis first and multi-turn sessions second **[AR]** ([arXiv 2509.23045](https://arxiv.org/abs/2509.23045v3)).

For a brand-new language, PyLang is the template. Claude Opus 4.5, working in an agentic loop with up to two interpreter-error retries, solved 2,250 of 9,269 problems, a **30.4% yield**. SFT on those solutions took Qwen3 4B, 8B and 32B from **0–7% to 36.1%, 38.6% and 47.2%**, against 47.7–63.6% in Python. DPO, GRPO and data scaling did not close the remaining gap, which was dominated by "same algorithm, wrong implementation" **[AR]** ([arXiv 2605.15607](https://arxiv.org/html/2605.15607v2)). MultiPL-T showed that translating high-resource solutions and filtering them by tests works where self-instruct fails, taking OCaml from 6.9% to 19.9% **[AR]** ([arXiv 2308.09895](https://arxiv.org/abs/2308.09895v2)). The strongest evidence that a small model can master a strict, checker-verified niche language comes from theorem proving. **Goedel-Prover-V2-8B reaches 84.6% pass@32 on miniF2F, beating DeepSeek-Prover-V2-671B at the same metric**, and verifier-guided self-correction adds about 2 points **[AR]** ([ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/13e8be77982beb73d7ed0bbf122f9f3c-Abstract-Conference.html)). RLEF trains the whole multi-turn error-to-fix loop with an outcome reward ([arXiv 2410.02089](https://arxiv.org/pdf/2410.02089)). Compiler and language-server diagnostics have been used as dense reward terms ([arXiv 2510.22907](https://arxiv.org/pdf/2510.22907)). CodeV-R1's Verilog work shows that oracle quality decides RL quality ([arXiv 2505.24183](https://arxiv.org/html/2505.24183v5)).

teagent's environment is structurally cheaper than any SWE gym. Qwen3-Coder ran 20,000 parallel environments and called environment scaling "the key challenge of Agent RL" ([Qwen](https://qwenlm.github.io/blog/qwen3-coder/)). One third party puts a SkyRL environment at more than one CPU and about 7 GB **[2nd]**. A Dartea rollout is an in-process interpretation plus an APFS clone only when the program calls `shell`. Its logs already hold everything a training set needs: the program, the compiler report, every tool result and the outcome. Those map onto SFT data (successful sessions, ideally those with a compile-error-to-fix turn), verifier data (all sessions labelled by outcome) and preference pairs. Two constraints shape the plan. The base must be stronger than the `qwen2.5-coder:7b` that solved 2–3 of 6–11 tasks: Qwen3-Coder-30B-A3B reached about 50% on SWE-bench Verified under Nebius's harness **[AR]** ([Nebius](https://nebius.com/blog/posts/openhands-trajectories-with-qwen3-coder-480b)), and Devstral Small 2 (24B dense, Apache-2.0) 68.0% **[AR]** ([Mistral](https://mistral.ai/news/devstral-2-vibe-cli/)). And the teacher must not be Claude without permission. Anthropic's terms bar using outputs to train competing models, and its March 2026 support article prohibits outputs as training targets for open-ended generation models ([Claude support](https://support.claude.com/en/articles/12326764)). OpenThoughts-Agent found an open-weight teacher, GLM-4.7, to be a *better* data generator than GPT-5.3-Codex, and keeping only traces of five or more turns helped significantly **[AR]** ([arXiv 2606.24855](https://arxiv.org/pdf/2606.24855)). No published work uses an Elm-like compiler as an RL reward. The nearest analogues are Lean and Verilog.

The vendor code modes use types only as prompt context and never check them ([Cloudflare](https://blog.cloudflare.com/code-mode/), [OpenAI](https://developers.openai.com/api/docs/guides/tools-programmatic-tool-calling)). Claude Code with `srt` contains the process but cannot rewind what bash did ([docs](https://code.claude.com/docs/en/checkpointing)).

## Seven research questions teagent is placed to own

The gaps across the notes converge on a niche no surveyed system occupies: **a pure, statically typed TEA language whose effect interpreter does staging, replay, refusal and provenance in one semantics.** The questions below are the sharpest research claims that niche supports. Each is open in the literature reviewed here, and each has a first result within reach of teagent's current code.

| # | Question | Why it is open | First publishable result |
| --- | --- | --- | --- |
| RQ1 | Can static noninterference be enforced for LLM-written TEA programs by indexing `Task` with labels (`Tainted a` with a pure `map` and no eliminator into an untainted `Task`), at acceptable utility? | tacit does static capabilities in Scala; CaMeL and FIDES are dynamic, and labels are lost across turns; the security report found no static noninterference typing for any agent DSL | a noninterference theorem for the `Task` core plus utility and attack success on an injection suite, against teagent's own dynamic labels on the same tasks: the first static-vs-dynamic IFC comparison with model and tasks held fixed |
| RQ2 | Is the staging handler sound: does committing the overlay after a run with no refusals equal direct execution, and does every effect appear in the log (trace transparency)? | ETAS proves trace transparency for its own language; λA shows Coq mechanization is feasible; Temporal-style systems have no such theorem | a mechanized proof for a core calculus of `Task`, the overlay and boot layers, plus property tests that check the OCaml handler against it |
| RQ3 | Do "live holes" (expected type, type definitions, ranked target-type headers and runtime values with labels) beat static-only hole context? | Hazel evaluated static context only; no paper evaluates type plus live-value context | hole-fill success on an MVUBench port to Dartea and on teagent's bench, across four context conditions, k = 5 |
| RQ4 | On coding benchmarks, what do typed-and-checked programs buy over untyped code and over JSON calls, holding model, sandbox and handler fixed? | no three-way study exists; no code-vs-JSON comparison exists on SWE-bench- or Terminal-Bench-class tasks | a factorial study with cache-adjusted $ per solved task, a crossover analysis by task shape, and compile rejections counted as caught failures |
| RQ5 | Can a pure DSL's compiler serve as a staged RL reward (parse, then typecheck, then plan, then outcome) without inviting reward hacking? | Lean and Verilog analogues only; PyLang found RL added little on single-shot code but did not test multi-turn compiler feedback | a ≤35B open model trained on 2–3k verified Dartea tasks, with ablations of reward stages and of the multi-turn feedback |
| RQ6 | Do mergeable branches (`spawn`/`merge` over overlays) make tree search and best-of-N cheaper or better than keep-or-discard snapshots, and is speculation over staged writes lossless? | BPO and DeltaBox fork but cannot merge; speculative actions are limited to side-effect-free calls | best-of-N and BPO-style branching through `spawn`, with snapshot overhead reported as a share of step time, plus a losslessness argument for speculating through `Staged` calls |
| RQ7 | Can inference over plans, meaning SMC whose particles are partial Dartea programs weighted by typecheck, plan and test potentials, beat sampling and retrying? | GenLM does SMC over strings; no paper does it over agent programs; teagent's IR interpreter can clone state, which multi-shot inference needs | pass@1 at equal token budget against best-of-N on hole-heavy tasks |

Two smaller contributions fall out of the same work. One is a short **effect-class spec for MCP tools** (`Pure`, `Staged`, `Contained`, `Egress`, `Irreversible`, plus commit and abort), since MCP's annotations are self-declared hints and no standard carries effect semantics. The other is **budgets as effects**, token and time quotas in the OS value and in `spawn`, for which the search found no prior work.

## Conclusion

The most useful change in perspective is that teagent no longer needs to argue that programs beat tool calls, or that types should be checked before execution. In 2026 the field produced that evidence and those systems itself. What it did not produce is a single semantics that ties the typed program to transactional, replayable, provenance-carrying effects. teagent's contribution is therefore not one of its mechanisms in isolation. It is the claim that holding the whole typed program before the first effect turns problems others solve online (taint tracking, temporal monitoring, speculation, rollback) into properties checked once, ahead of time, and replayed exactly. That claim is strong and plausible, and it is unproven.

The evaluation literature also shows that a runtime is now a first-class research object. When the harness moves scores more than the model, a harness paper with factorial controls, cost per solved task and replayable logs is a central contribution, not a side note. teagent's cheapest path to leadership runs through measurement it can already perform: its own MCP server gives it the cleanest tools-vs-program control anyone has published. Its most durable path runs through two theorems, noninterference for a label-indexed `Task` and soundness of the staging handler. They are small enough to prove because Elm already did most of the work.
